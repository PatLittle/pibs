# Network Monitoring using Secure Cloud Enablement and Defense (SCED) – Enterprise Security Service Edge (ESSE)

## Description

Enterprise Security Service Edge (ESSE) is a cloud-based security service implemented by Shared Services Canada (SSC) to monitor and protect network and cloud-based activities. It enables SSC to inspect and manage internet and cloud application traffic across SSC-managed devices, including Software-as-a-Service platforms such as Microsoft 365.

ESSE supports secure access to applications and the internet by applying security policies, detecting potential threats, and enforcing compliance requirements. It leverages technologies such as secure web gateways, cloud access security broker capabilities, proxy services, and Zero Trust Network Access to provide visibility into network activity and protect government network assets.

The service collects and analyzes network activity data (such as user identifiers, device information, traffic patterns, and access activity) to detect security threats, support incident response, and ensure compliance with security policies.

## Why a privacy impact assessment was completed

A Privacy Impact Assessment (PIA) was conducted to evaluate the privacy implications of implementing ESSE as part of SSC’s network security and cloud monitoring capabilities.

The PIA was required because the program introduces enhanced monitoring of user activity across cloud services and internet traffic, involving the collection and processing of personal information such as user identifiers and activity logs. It also reflects important changes to SSC’s network perimeter security approach and the deployment of new solutions on SSC-managed devices.

The assessment ensures that privacy risks are identified, mitigated, and aligned with applicable legislation, including the Shared Services Canada Act and the Privacy Act, while supporting SSC’s mandate to protect government IT infrastructure.

## Additional information

The PIA identified several key privacy risks and corresponding mitigation measures:

1. **Accountability risks**

   Multiple parties (SSC, the vendor, and the Canadian Centre for Cyber Security) may have custody or access to personal information.

   Mitigation: Strengthening documentation of data custody, control, and access arrangements, including oversight of vendor and partner responsibilities.
2. **Limiting use, disclosure, and retention**

   Personal information is shared with authorized federal partners for cybersecurity purposes, which must be clearly reflected in documentation.

   Mitigation: Maintaining clear agreements, defined roles and responsibilities, and strong safeguards such as encryption, access controls, and audit logging.
3. **Safeguards and security controls**

   Some enterprise-level controls required ongoing monitoring or mitigation.

   Mitigation: Continued tracking through security governance processes and implementation of mitigation plans identified in security assessments.

Additional compliance actions include improving documentation of data flows and exclusions, enhancing transparency around automated analytics, and strengthening processes for access and compliant handling.
